## 结论

**核心记账和备份恢复已经能形成可靠的基本使用闭环；当前更需要修复现有功能的一致性与布局问题。**

**当前不建议继续堆功能。优先修复 F01，再修 F02–F04；F05 单独作为加固建议处理。** 这些改进不需要新增系统权限。源码已补充，但本轮仍未实施应用修复。

## 确认的问题与优先级

### F01 · P1：新增账户页的保存操作被状态栏遮挡

复现：我的 → 账户管理 → 新增账户 → 填入 `ReviewBank` → 选择储蓄卡。页面标题、关闭和保存被放在系统状态栏所在区域，与时钟、电量重叠。UI 树没有正常可点击的“保存”文本节点；点击画面中保存所在位置后仍留在编辑页，返回账户列表仍只有现金账户。

影响：本次设备上不能完成账户创建，连带阻挡双账户转账的界面验收。这不是单纯的视觉细节，应最先处理。具体源码根因尚未确认，不将模拟器上的现象扩大为所有设备必现。

修复方向：检查账户编辑页是否绕过统一导航组件及顶部安全区处理。以实际避让区布局标题和操作，避免硬编码顶部坐标；无需新增权限。参考 [华为系统避让区说明](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-arkui-1089)。

证据：[新增账户截图](review/screenshots/account-edit.jpeg)。

### F02 · P2：预算输入时，保存按钮被键盘遮挡

复现：首页 → 去设置预算 → 点击输入框 → 输入 200。键盘弹出后，保存按钮的可见布局高度由约 147px 裁至约 24px，文字被挡住；收起键盘后才能正常点击保存。

影响：用户容易误以为没有提交入口，额外增加一次收键盘操作。页面内容在未输入时垂直位置较低，也放大了这一问题。

修复方向：调整表单的滚动、定位与键盘避让，保持提交入口可见，不增加功能或权限。

证据：[预算键盘遮挡截图](review/screenshots/budget-keyboard.jpeg)。

### F03 · P2：预算使用比例向上取整，显示误导

复现：预算设为 200 元，累计支出 0.02 元。准确比例为 `0.02 ÷ 200 × 100% = 0.01%`，实际显示 `1%`。字节码中的 `BudgetProgressCard.usedPercent` 确认使用 `Math.ceil` 计算整数百分比。

影响：这是显示口径失真，没有发现账目金额因此被改动。极小消费的显示相差 100 倍，容易影响用户理解。

修复方向：展示合理小数位，或在低于 1% 时显示“<1%”；图形的最小可见弧长与文字比例分开处理。

证据：[百分比截图](review/screenshots/budget-small-percentage.jpeg)、[函数指令](review/sql-results.json)。

### F04 · P2：切换显示币种后，首页最近记录未同步刷新

复现：已有两笔 0.01 元支出 → 我的 → 主题与货币 → 美元，保留手动汇率 7.2 → 返回首页。汇总显示 `$13.89`，最近记录仍显示 `¥0.01`。再切换明细页，明细金额已显示美元；返回首页后最近记录依然是人民币。

影响：同一设置在不同列表上表现不一致，让用户难以判断金额口径。这里确认的是显示问题，没有证据表明数据库金额被错误换算。

修复方向：检查最近记录组件对显示货币、汇率状态的依赖与刷新；统一金额展示入口。无需实时汇率、联网或新权限。

证据：[深色与美元首页截图](review/screenshots/dark-usd.jpeg)。

### F05 · P2：应用锁缺少已观察到的重试节制，PIN 派生较弱

动态结果：设置四位测试 PIN，冷启动进入锁屏；连续输入十次错误 PIN，均被拒绝，但没有出现等待或锁定，随后立即输入正确 PIN 即可解锁。结论限于这十次尝试，未声称已证明无限次都不限制。

静态结果：`PIN_LENGTH=4`；`CryptoUtil.hashPin` 拼接 PIN 与盐后调用 `sha256Hex`，后者进行一次 SHA-256，没有在该调用链中看到迭代式密码派生。盐来自系统随机数接口，这是正面设计，但四位 PIN 只有 10,000 个组合。

影响：能挡住随手查看；不能表述为强数据加密。如果攻击者另行获取 PIN 校验材料，快速哈希对离线枚举的保护有限。**本次没有读取真实用户 PIN，也没有证明应用沙箱可被普通应用读取。**

修复方向：增加本地失败次数与等待策略，采用适合 PIN 的派生及保护方案；不需要新增权限。快速 SHA-256 与密码派生方案的区别见 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

证据：[锁屏截图](review/screenshots/lock.jpeg)、[hashPin 与 SHA256 调用证据](review/sql-results.json)。

## 正面评价及依据

- **金额处理有基础。** 字节码确认按整数分解析并检查安全整数与金额范围；实际两笔 0.01 元累加、收支与余额结果一致。
- **恢复流程有防御。** 不只存在备份入口：有效备份完成恢复；损坏 JSON、高版本和错误账户关联均被真实拒绝。字节码还有字段、行数及关联校验，恢复写入经过统一事务入口。
- **存储有工程组织。** 七张业务表和七个显式索引；预算具有“账本 + 月份”唯一索引。`DatabaseManager.runInTransaction` 有串行排队、提交与回滚路径。未对异常中断回滚做故障注入。
- **本地优先设计清楚。** 已安装应用请求权限为空；此次流程使用系统文件选择器，无需授予应用存储权限。诊断样本未暴露 PIN 或账单明细。
- **界面有统一风格。** 卡片、圆角、主色、金额颜色和深色模式总体一致，主要页面与空态具备完整外观。账户编辑的安全区异常说明一致性还没有覆盖到所有页面。

架构层面识别到 24 个页面、103 条模块路径，涉及页面、ViewModel、Service、模型、组件和工具。这是模块组织的证据，不能替代源码质量审查，也不按文件数量推断质量。

## 复核方法

先用仓库工具确认提取资料仍与原包一致：

```powershell
python tools/unpack_app.py --check
python -m unittest discover -s tools -p "test_*.py"
```

用 SDK 自带反汇编工具生成本地分析文件，再执行原 SQL 的合成数据复核：

```powershell
ark_disasm recovered/entry/ets/modules.abc local-data/review/modules.pa
python tools/audit_existing_package.py --disassembly local-data/review/modules.pa --output local-data/review/sql-results.json
```

SQL 复核覆盖表结构与索引、月初包含/月末排除、账本隔离、转账排除、账户余额和预算唯一性。它使用从包中提取的查询，不执行应用 Service、ViewModel 或 UI；不能替代上面的实际界面测试。

界面复核须在独立测试设备上使用合成数据，按本报告步骤执行。HDC、UI 树和导出原件的本地操作记录保存在被 Git 忽略的 `local-data/review/`，仓库保留结果摘要及截图；测试模拟器仅用于本轮验证。
